## 3. Detailed Technical Findings

### Finding F-057: `enable_automation` Fails to Clear `_cycle_seen_in_pass`, Bypassing and Starving Re-Enabled Failed `P0` Reports

#### 1. Observation
When a Lane A report (`P0_Crit`) exhausts its retries and transitions to `Failed` in [`IntradayService._trigger_report._handle_failure`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/services/intraday_service.py#L933), the engine discards it from `self._cycle_pass_reports` (`self._cycle_pass_reports.discard(name)`) **without removing it from `self._cycle_seen_in_pass`**.

When an operator subsequently fixes the issue and clicks **`▶ Enable`** (`POST /api/automation/enable`), [`AutomationController.enable_automation()`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/controllers/automation_controller.py#L278-L286) inserts the report into `waitlist` via `_enqueue_lane_a_by_priority(name)` and adds it to `_cycle_pass_reports`, **but fails to discard `name` from `self._cycle_seen_in_pass`**.

#### 2. Evidence
1. In `AutomationController.enable_automation()` (lines 278–286):
   ```python
   if report.report_type == "type_a" and self.intraday_service.lane_a_active:
       day = self.intraday_service.intraday_repo.get_day(today_date)
       already_ran = self.intraday_service._get_completed_or_exhausted_reports(day) if day else set()
       if name not in already_ran and name not in self.intraday_service.waitlist and name not in self.intraday_service.current_runs:
           self.intraday_service._enqueue_lane_a_by_priority(name)
           self.intraday_service.all_completed = False
           self.intraday_service._rotation_cooldown_until = 0.0
           self.intraday_service._cycle_pass_reports.add(name)
           # OMISSION: self.intraday_service._cycle_seen_in_pass.discard(name) is never called!
   ```
2. In `IntradayService.tick()` (line 648):
   ```python
   unseen_candidates = [r for r in self.waitlist if r not in self._cycle_seen_in_pass]
   ```
   Because `name` is still in `_cycle_seen_in_pass`, `tick()` excludes the newly re-enabled `P0_Crit` from `unseen_candidates`, even though `_enqueue_lane_a_by_priority("P0_Crit")` placed `P0_Crit` at index `0` of `waitlist` (`['P0_Crit', 'P2_Norm']`)!
3. **Reproduced in Sandbox:** Running `poc_f057_f060_lane_a_multi_angle_attacks.py` confirms that after `P0_Crit` fails and is re-enabled while `P2_Norm` is waiting, `'P0_Crit'` remains in `_cycle_seen_in_pass` and `tick()` dispatches `'P2_Norm'` ahead of `'P0_Crit'`.

#### 3. Consequence
- Violates Invariant `I-1` (Priority-FIFO ordering `P0 -> P1 -> P2`) and `I-8` (Queue / Memory State Convergence).
- Downstream `P1`/`P2` reports that depend on `P0_Crit` are forced to execute before the newly recovered `P0_Crit` report.
- When `max_concurrent_run > 1` and a concurrency slot is open while another job is running, the re-enabled `P0_Crit` is not dispatched into the open slot because `unseen_candidates` is empty and `len(current_runs) > 0`.

#### 4. Verification Criterion
1. When a report permanently fails in `_handle_failure`, or when a report is re-enabled in `AutomationController.enable_automation()`, its name MUST be evicted from `self._cycle_seen_in_pass`.
2. A re-enabled `P0` report in Lane A MUST be treated as unseen in the active pass and dispatched ahead of lower-priority `P1`/`P2` reports on the next `tick()`.

### Finding F-058: Terminal Completion or Failure of the Final Report in a Pass Leaves Pass Counters Dirty, Bypassing Starvation Cooldown

#### 1. Observation
In [`IntradayService._trigger_report._on_good`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/services/intraday_service.py#L856-L879) (on `Completed`) and [`_handle_failure`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/services/intraday_service.py#L933-L952) (on permanent `Failed`), `self._cycle_pass_reports.discard(name)` is executed **prior** to calling `self._evaluate_pass_completion(date)`.

When the final remaining report in the queue completes or permanently fails, `self._cycle_pass_reports` becomes an empty set `set()`. Consequently, line 123 of [`_evaluate_pass_completion()`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/services/intraday_service.py#L123):
```python
if self._cycle_pass_reports and self._cycle_pass_reports.issubset(self._cycle_seen_in_pass):
```
evaluates to `False` and returns immediately without resetting `_cycle_completions_in_pass`, `_cycle_errors_in_pass`, `_cycle_skips_in_pass`, or `_cycle_seen_in_pass`.

#### 2. Evidence
1. After the queue drains (`waitlist` is empty and `_cycle_pass_reports` is `set()`), `self._cycle_completions_in_pass` remains `>= 1` (or `self._cycle_errors_in_pass` remains `>= 1`).
2. When an operator subsequently adds a new report (`POST /api/automation/add`) or enables a report (`POST /api/automation/enable`) later in the same day, and that report skips due to an unready dependency, `_evaluate_pass_completion()` checks:
   ```python
   if self._cycle_skips_in_pass > 0 and self._cycle_completions_in_pass == 0 and self._cycle_errors_in_pass == 0 and len(self.waitlist) > 0:
       cooldown = self.get_rotation_cooldown()
       self._rotation_cooldown_until = time.time() + cooldown
   ```
   Because `self._cycle_completions_in_pass` (or `self._cycle_errors_in_pass`) is still non-zero from the earlier drained pass, `self._cycle_completions_in_pass == 0 and self._cycle_errors_in_pass == 0` evaluates to `False`.
3. **Reproduced in Sandbox:** Running `poc_f057_f060_lane_a_multi_angle_attacks.py` (`test_f058_terminal_completion_of_last_pass_report_leaves_counters_dirty`) fails with:
   ```
   AssertionError: 0.0 not greater than 1790962857.3166134 : F-058: Stale _cycle_completions_in_pass from drained pass prevented starvation cooldown!
   ```

#### 3. Consequence
- Violates Invariant `I-2` and `F-005` (Starvation Cooldown Enforcement).
- Newly added or re-enabled reports that skip after the initial queue has drained bypass the 30-second starvation cooldown and immediately re-execute back-to-back.

#### 4. Verification Criterion
1. When all reports in a pass have completed or failed (including when `_cycle_pass_reports` becomes empty and `len(self.current_runs) == 0`), `_evaluate_pass_completion()` MUST reset `_cycle_seen_in_pass`, `_cycle_completions_in_pass = 0`, `_cycle_skips_in_pass = 0`, and `_cycle_errors_in_pass = 0`.
2. Any report added or enabled after a drained pass that subsequently skips on dependencies MUST engage the starvation cooldown at the end of its pass.

### Finding F-059: `start_lane("type_a")`, `stop_lane("type_a")`, `start_fresh_run()`, and `reset_all_reports()` Fail to Reset `_cycle_skips_in_pass` and `_cycle_errors_in_pass`

#### 1. Observation
Across four lifecycle methods in [`paradiso/services/intraday_service.py`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/services/intraday_service.py):
- `start_lane("type_a")` (lines 363–367)
- `stop_lane("type_a")` (lines 401–405)
- `start_fresh_run()` (lines 492–496)
- `reset_all_reports()` (lines 528–532)

only `self._cycle_completions_in_pass = 0` is reset, while **`self._cycle_skips_in_pass` and `self._cycle_errors_in_pass` are never reset to `0`**.

#### 2. Evidence
1. In `start_lane("type_a")`, `stop_lane("type_a")`, `start_fresh_run()`, and `reset_all_reports()`:
   ```python
   self._rotation_cooldown_until = 0.0
   self._cycle_pass_reports.clear() # or set(self.waitlist)
   self._cycle_seen_in_pass.clear()
   self._cycle_completions_in_pass = 0
   self._last_rotation_logged.clear()
   # OMISSION: _cycle_skips_in_pass and _cycle_errors_in_pass are not reset!
   ```
   Contrast with midnight rollover in `tick()` (lines 606–608), which resets all three counters (`_cycle_completions_in_pass = 0`, `_cycle_skips_in_pass = 0`, `_cycle_errors_in_pass = 0`).
2. **Reproduced in Sandbox:** Running `poc_f057_f060_lane_a_multi_angle_attacks.py` (`test_f059_lifecycle_methods_fail_to_reset_skips_and_errors_in_pass`) fails with:
   ```
   AssertionError: 2 != 0 : F-059: stop_lane('type_a') must reset _cycle_errors_in_pass to 0
   ```

#### 3. Consequence
- Violates Invariant `I-2`, `I-8`, and `F-005`.
- If a report encounters an error mid-pass and the operator stops Lane A (or clicks **Reset All Reports**) before the pass ends, `_cycle_errors_in_pass` remains `> 0` after restarting Lane A, preventing starvation cooldown from engaging on the first pass of dependency skips.

#### 4. Verification Criterion
- `start_lane("type_a")`, `stop_lane("type_a")`, `start_fresh_run()`, and `reset_all_reports()` MUST all reset `self._cycle_skips_in_pass = 0` and `self._cycle_errors_in_pass = 0`.

### Finding F-060: Deferred `_cycle_seen_in_pass` Clearing (`defer_seen_clear=True`) on `disable_automation` Inverts Priority Order and Starves `P0` Reports When Reports Are Added/Enabled

#### 1. Observation
In [`AutomationController.disable_automation()`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/controllers/automation_controller.py#L230), `_evaluate_pass_completion()` is called with `defer_seen_clear=True`:
```python
self.intraday_service._evaluate_pass_completion(CLOCK.date_str(), defer_seen_clear=True)
```
When disabling an idle report completes the current pass, `_evaluate_pass_completion()` engages the 30s starvation cooldown and resets `_cycle_pass_reports = set(self.waitlist)`, `_cycle_skips_in_pass = 0`, and `_cycle_completions_in_pass = 0`, **but leaves the completed pass's reports inside `self._cycle_seen_in_pass`**.

If an operator adds (`POST /api/automation/add`) or enables (`POST /api/automation/enable`) a lower-priority `P2` report before the next tick (e.g., during the 30-second cooldown), `_enqueue_lane_a_by_priority()` sees the existing `P0` report in `_cycle_seen_in_pass` and inserts the `P2` report **ahead** of the `P0` report. Furthermore, on the next `tick()`, `unseen_candidates` is non-empty (`['RepD_P2']`), so the fallback check `if ... and not unseen_candidates:` never triggers, `_cycle_seen_in_pass` is never cleared, `RepD_P2` executes ahead of `RepB_P0`, and Pass 2 ends immediately without `RepB_P0` executing at all!

#### 2. Evidence
1. In `IntradayService._enqueue_lane_a_by_priority()`:
   ```python
   for idx, existing in enumerate(items):
       if existing in self._cycle_seen_in_pass or self._priority_rank(existing) > target_rank:
           insert_idx = idx
           break
   ```
   Because `RepB_P0` was left in `_cycle_seen_in_pass` after Pass 1 completed in `disable_automation()`, `existing in self._cycle_seen_in_pass` matches at `idx = 0`, placing `RepD_P2` ahead of `RepB_P0` (`['RepD_P2', 'RepB_P0']`).
2. In `IntradayService.tick()` (lines 648–651):
   ```python
   unseen_candidates = [r for r in self.waitlist if r not in self._cycle_seen_in_pass]
   if len(self.current_runs) == 0 and len(self.waitlist) > 0 and not unseen_candidates:
       self._evaluate_pass_completion(today_date)
       unseen_candidates = [r for r in self.waitlist if r not in self._cycle_seen_in_pass]
   ```
   Because `unseen_candidates` is `['RepD_P2']` (non-empty), `tick()` does not clear `_cycle_seen_in_pass`, dispatches `RepD_P2`, and when `RepD_P2` skips, `{'RepB_P0', 'RepD_P2'}.issubset(_cycle_seen_in_pass)` is immediately `True`, ending Pass 2 without `RepB_P0` ever running!
3. **Reproduced in Sandbox:** Running `poc_f057_f060_lane_a_multi_angle_attacks.py` (`test_f060_defer_seen_clear_on_disable_inverts_priority_and_starves_p0_pass`) fails with:
   ```
   AssertionError: Lists differ: ['RepD_P2', 'RepB_P0'] != ['RepB_P0', 'RepD_P2']
   ```

#### 3. Consequence
- Violates Invariant `I-1` (Priority-FIFO ordering `P0 -> P1 -> P2`) and `I-8` (Queue / Memory State Convergence).
- A `P0` Critical report is both demoted behind `P2` Normal reports and completely skipped for an entire pass whenever an idle report is disabled at the end of a pass followed by a report addition or enablement.

#### 4. Verification Criterion
1. `_evaluate_pass_completion()` MUST unconditionally clear `self._cycle_seen_in_pass` whenever a pass completes (including when invoked from `disable_automation()`), without deferring `_cycle_seen_in_pass.clear()`.
2. Both `poc_f056_disable_queue_deadlock.py` and `poc_f057_f060_lane_a_multi_angle_attacks.py` MUST pass 100%.
