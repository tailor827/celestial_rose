### [F-076] [LOW] Stale `ExecutionService` status write after `reset_all_reports()` / `_close_day()`

- **OBSERVATION:**
  1. `ExecutionService.execute_report` defines its own `_on_good` / `_on_fail` closures ([`execution_service.py:68-128`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/services/execution_service.py#L68-L128)). They call `automation_service.update_status(...)` first, and only then invoke `IntradayService`'s callback, where the new `if name not in self.current_runs: return` guard lives ([`intraday_service.py:1043-1047`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/services/intraday_service.py#L1043-L1047)). The `IntradayService` guard therefore stops the ledger write but not the catalog write.
  2. The guard inside `ExecutionService` (lines 69-71 and 109-111) only skips when status is `Waiting` **and** `last_output == "Stopped by user"`. That covers `stop_lane()` only. `reset_all_reports()` sets `Waiting` without that message (`set_waiting_all`), and `_close_day()` sets `Failed` with `"Forcibly terminated..."`.
  3. `Runner._watcher` suppresses callbacks only for processes flagged by `kill_all()`/`kill_process()`. A process that already exited (and was popped from `active_processes`) before the kill is not flagged, so its callback still runs.
  4. The Batch 16 F-072 PoC replaced `execute_report` with a fake, so it never exercised these `ExecutionService` closures. That is why F-072 passed while this path remained open.

- **EVIDENCE:**
  ```text
  $ python artifacts/audits/poc/poc_f076_lane_a_stale_exec_write.py
  [F-076a reset]    launched=True, status_after=Completed, still_pending=False -> FAIL (BUG CONFIRMED)
  [F-076b close]    launched=True, catalog_status=Completed, intraday_ledger=failed -> FAIL (BUG CONFIRMED)
  ```

- **CONSEQUENCE:**
  1. **Reset All:** the finishing report is written back as `Completed`. `get_pending_by_type` excludes `Completed`, so after the operator's reset that report is silently dropped from the rest of the day's Lane A queue.
  2. **22:00 cutoff:** `automations.json` says `Completed` while `intraday.json` records `failed` ("Forcibly terminated..."). The UI and the day ledger disagree for that report.
  The window is narrow (the process must exit between its natural end and the reset/cutoff acquiring the lock), but it is reachable in production.

- **VERIFICATION CRITERION:**
  A callback from a run that `IntradayService` no longer tracks (after `stop_lane`, `reset_all_reports`, `_close_day` or midnight rollover) must not modify `automations.json` or `intraday.json`. Both PoC scenarios must PASS: after Reset All the report stays `Waiting` and pending; after the cutoff, catalog status matches the intraday ledger.
