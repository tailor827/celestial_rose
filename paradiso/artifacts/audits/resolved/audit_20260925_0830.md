## 3. ADVERSARIAL DOSSIERS (STANDARD TRIAD)

### F-021: Exact Receipt Naming Mismatch in Type B & C Pipeline Scripts
- **Severity:** CRITICAL
- **Confidence:** CONFIRMED
- **Category:** RECEIPT CONTRACT
- **Target Invariants:** I-7 (Honest API), I-8 (Queue / Storage / Memory Convergence)
- **PoC Verification:** [`artifacts/audits/poc/poc_f021_receipt_mismatch.py`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/artifacts/audits/poc/poc_f021_receipt_mismatch.py)
- **Observation:**
  `reports/hourly_liquidity_feed.py` defines `REPORT_NAME = "Hourly_Liquidity_Feed"` and writes receipts named `Hourly_Liquidity_Feed.json`. Similarly, `reports/eod_ledger_reconciliation.py` defines `REPORT_NAME = "EOD_Ledger_Reconciliation"` and writes receipts named `EOD_Ledger_Reconciliation.json`.
  However, in `storage/automations.json`, the registration keys and report names are `"Hourly Liquidity Feed"` and `"EOD Ledger Reconciliation"` (separated by spaces).
- **Evidence:**
  In `models/report_log.py`, `find_latest_log_file()` searches for exact matches (`f"{self.name}.json"`) or prefix patterns (`f"{self.name}_*.json"`). When queried with `"Hourly Liquidity Feed"` or `"EOD Ledger Reconciliation"`, `find_latest_log_file()` produces `None`, and `has_valid_receipt()` returns `False`.
  Empirical run with `poc_f021_receipt_mismatch.py` demonstrates:
  ```text
  [+] ReportLog('Hourly Liquidity Feed').find_latest_log_file(): None (has_valid_receipt: False)
  [+] ReportLog('EOD Ledger Reconciliation').find_latest_log_file(): None (has_valid_receipt: False)
  ```
- **Consequence:**
  Whenever `Hourly Liquidity Feed` or `EOD Ledger Reconciliation` finishes execution, the engine evaluates `find_latest_log_file()` as `None`. Under Section 12 of the technical specification, absence of a matching receipt is treated as a contract violation, logging an unverified execution state and failing receipt verification.
- **Verification Criterion:**
  Receipt files generated by `hourly_liquidity_feed.py` and `eod_ledger_reconciliation.py` must match the registered automation names such that `ReportLog(name).find_latest_log_file()` and `has_valid_receipt()` return truthy valid file handles for their respective registered keys in `storage/automations.json`.

### F-022: Unbounded 500ms Rapid Spin on Dependency Skips in Lane B and Lane C
- **Severity:** HIGH
- **Confidence:** CONFIRMED
- **Category:** QUEUE & CONCURRENCY
- **Target Invariants:** I-2 (Dependency Wait vs Error Retry), I-6 (Storage Atomicity & Durability)
- **PoC Verification:** [`artifacts/audits/poc/poc_f022_lane_b_c_spin.py`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/artifacts/audits/poc/poc_f022_lane_b_c_spin.py)
- **Observation:**
  When a report in Lane B or Lane C encounters a missing dependency and emits a skip receipt / exits with code 1, the scheduler fails to apply a backoff cooldown or advance its scheduling state:
  1. In `_trigger_type_b_report`, `_on_fail` pops `active_runs_type_b` but does not record `self.type_b_last_run[name] = CLOCK.now()`.
  2. In `_trigger_type_c_report`, neither `_on_good` nor `_on_fail` records a cooldown or marks `self.type_c_ran_today.add(name)` upon a dependency skip.
- **Evidence:**
  In `IntradayService.tick()`, Lane B evaluates `last_run is None or elapsed >= interval_sec`, and Lane C evaluates `rep.name not in self.type_c_ran_today and current_hhmm >= target_time`.
  Because `type_b_last_run` is unrecorded on skip, and `type_c_ran_today` remains unpopulated, the scheduler immediately re-dispatches the report on the next tick.
  Empirical run with `poc_f022_lane_b_c_spin.py` over 5 simulated 500ms ticks confirms:
  ```text
  [+] Testing Lane B rapid spin on dependency skip (exit code 1)...
      Ticks simulated: 5
      Dispatches triggered: 5
      [!] CONFIRMED Lane B rapid spin: 60-minute task re-executes every 500ms on dependency skip!
  [+] Testing Lane C rapid spin on dependency skip...
      Ticks simulated: 5
      Dispatches triggered: 5
      [!] CONFIRMED Lane C rapid spin: Once-per-day task re-executes every 500ms on dependency skip!
  ```
- **Consequence:**
  When upstream data feeds or ledger batches are delayed, Lane B reports (configured for 60-minute intervals) and Lane C reports (configured for single daily execution) launch repeatedly every 500ms. This produces CPU starvation, timeline event flooding, storage write amplification, and process churn until the 22:00 cutoff.
- **Verification Criterion:**
  When a Type B report skips due to missing dependencies, its next execution must be throttled by an interval cooldown. When a Type C report skips due to missing dependencies, it must not execute repeatedly on consecutive 500ms scheduler ticks while waiting for its dependencies to arrive.

### F-023: BG-001 Idle-Only Settings Guardrail Bypassed for Type B and C Runs
- **Severity:** HIGH
- **Confidence:** CONFIRMED
- **Category:** SECURITY & INTEGRITY
- **Target Invariants:** BG-001 (Idle-Only Settings Guardrail), I-7 (Honest API), I-9 (Security Boundaries)
- **PoC Verification:** [`artifacts/audits/poc/poc_f023_bg001_lane_b_c_bypass.py`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/artifacts/audits/poc/poc_f023_bg001_lane_b_c_bypass.py)
- **Observation:**
  `SettingsController.update_settings()` evaluates whether the engine is active using:
  ```python
  is_active = False
  if self.paradiso and self.paradiso.is_running():
      is_active = True
  elif self.intraday_service and (self.intraday_service.is_active or len(self.intraday_service.current_runs) > 0):
      is_active = True
  ```
  The guardrail inspects `current_runs` (Lane A), but fails to inspect `active_runs_type_b` or `active_runs_type_c`.
- **Evidence:**
  When a manual run of a Type B or Type C report is triggered via `POST /api/automation/run` while the scheduler loop is idle, `active_runs_type_b` or `active_runs_type_c` contains an active running process.
  Submitting a mutation to `POST /api/settings` yields HTTP `200 OK` (`{"ok": true, "message": "Configuration saved and applied successfully."}`) rather than HTTP `409 Conflict`.
  Empirical run with `poc_f023_bg001_lane_b_c_bypass.py` confirms:
  ```text
  [+] Type A active in current_runs -> HTTP 409 (Expected 409 Conflict)
  [+] Testing Settings mutation while Lane B report is active...
      Settings POST returned HTTP 200 with body: {'message': 'Configuration saved and applied successfully.', 'ok': True, ...}
      [!] CONFIRMED: Settings modified while Lane B process running (Bypassed BG-001 guardrail)!
  [+] Testing Settings mutation while Lane C report is active...
      Settings POST returned HTTP 200 with body: {'message': 'Configuration saved and applied successfully.', 'ok': True, ...}
      [!] CONFIRMED: Settings modified while Lane C process running (Bypassed BG-001 guardrail)!
  ```
- **Consequence:**
  Operators or automated scripts can alter Python executable paths, storage paths, and simulation settings mid-execution while Type B and Type C jobs are active, violating configuration immutability guarantees.
- **Verification Criterion:**
  `SettingsController.update_settings()` must return HTTP 409 Conflict whenever ANY task is actively executing, including jobs tracked in `active_runs_type_b` and `active_runs_type_c`.

### F-024: Input Validation Laxity on Lane Names in `lane_start` and `lane_stop`
- **Severity:** LOW
- **Confidence:** CONFIRMED
- **Category:** API CONTRACT
- **Target Invariants:** I-7 (Honest API)
- **Observation:**
  In `IntradayService._normalize_lane(lane)`, any input string that does not contain `"b"` or `"c"` is defaulted to `"type_a"`:
  ```python
  def _normalize_lane(self, lane: str) -> str:
      l = str(lane or "").strip().lower()
      if "b" in l:
          return "type_b"
      if "c" in l:
          return "type_c"
      return "type_a"
  ```
- **Evidence:**
  Dispatching `POST /api/paradiso/lane/start` with payload `{"lane": "unrecognized_garbage"}` returns HTTP 200 OK with:
  `{"ok": true, "lane": "unrecognized_garbage", "message": "Lane 'unrecognized_garbage' started"}`
  while quietly starting Lane A (`type_a`).
- **Consequence:**
  Invalid API inputs are silently coerced into mutating Lane A rather than being rejected with HTTP 400 Bad Request, creating ambiguity for API clients and potential operational errors.
- **Verification Criterion:**
  `POST /api/paradiso/lane/start` and `POST /api/paradiso/lane/stop` must strictly validate that `lane` resolves to one of the canonical lane identifiers (`"type_a"`, `"type_b"`, `"type_c"`) and reject invalid inputs with HTTP 400.

## 4. TEST HARNESS HYGIENE OBSERVATION

- **Observation:**
  When executing unit test suites via `run_tests.py`, detached `_watcher` daemon threads and scheduler loops attempt to mutate temporary storage files after `tearDown()` has removed the temporary directory:
  ```text
  Exception in thread Thread-36 (_watcher):
  FileNotFoundError: [Errno 2] No such file or directory: '...\\automations_temp.json'
  ```
- **Impact:**
  While tests pass assertions before thread termination, unjoined background threads emit unhandled exceptions to stderr during test teardown.
- **Auditor Note:**
  This does not impact production runtime directly, but indicates loose thread joining during test harness cleanup.
