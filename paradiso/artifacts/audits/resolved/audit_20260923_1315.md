## 3. RE-AUDIT FINDINGS (RESOLUTIONS)

### F-006: Process watcher suppression via CPython heap address reuse
- **Status:** **RESOLVED**
- **Evaluation:**
  - Implemented monotonic launch counter `self._exec_counter: int` in `Runner` and assigned immutable integer `_exec_id` to each process launch under `self._proc_lock`.
  - Added object-level stamping `setattr(process, "_was_killed", True)` in `kill_all()`.
  - Replaced CPython virtual memory address checking (`id(process) in self.killed_process_ids`) with `proc_exec_id in self.killed_exec_ids`.
  - Removed the fragile name-fallback check (`name in self.killed_processes and self.active_processes.get(name) is not process`) from the `was_killed` condition.
  - **Adversarial Verification:** In `poc_f006_f008_verification.py`, a report (`Rapid_Recycle_Report`) was spawned and killed via `kill_all()`. A second process with the exact same report name was spawned immediately after; it completed cleanly and fired `callback_good` without being suppressed.

### F-008: Child process trees survive `Runner.kill_all()` on Windows
- **Status:** **RESOLVED**
- **Evaluation:**
  - In `Runner.kill_all()`, added Windows process tree termination using `taskkill /F /T /PID <pid>` with `CREATE_NO_WINDOW`.
  - Retained defensive fallback to `process.terminate()` and `process.kill()` for non-Windows platforms.
  - Added `process.wait(timeout=1.0)` to clean up terminated process handles.
  - **Adversarial Verification:** In `poc_f006_f008_verification.py`, a 3-tier deep process tree (Parent `PID 4368` -> Child `PID 11488` -> Grandchild `PID 23432`) was launched. Upon calling `runner.kill_all()`, Windows `tasklist` was queried; all three PIDs were confirmed dead. Zero orphan processes survived.

## 4. NEW FINDINGS

### F-013: Active automation broken due to deleted report script (`0base_auto.py`)

- **Severity:** HIGH
- **Confidence:** CONFIRMED
- **Category:** STORAGE / QUEUE
- **Invariant:** I-8 (Queue / Storage / Memory Convergence)
- **Location:** `storage/automations.json:2-15`, `reports/0base_auto.py` (deleted)

**OBSERVATION**  
The working tree commit deleted `reports/0base_auto.py`, `reports/eca_sf_ppp_auto.py`, and `reports/recov_sf_ppp_auto.py`. However, `storage/automations.json` still registers `"SF Base"` targeting `filename: "0base_auto.py"` in `../reports`.

**EVIDENCE**  
Lines 2–15 of `storage/automations.json`:
```json
{
    "SF Base": {
        "name": "SF Base",
        "filename": "0base_auto.py",
        "filetype": "python",
        "dir": "../reports",
        "status": "Waiting",
        "last_output": "Error (attempt 1/3): Report script not found on disk: ...\\reports\\0base_auto.py"
    }
}
```
When `SF Base` is triggered, `ExecutionService.execute_report` validates script existence on disk:
```python
if not script_path.exists():
    error_msg = f"Report script not found on disk: {script_path}"
    _on_fail("0s", error_msg)
    return False
```
Because the script was deleted, the execution fails immediately with `"Report script not found on disk"`, consuming error retries and failing the automation.

**CONSEQUENCE**  
The registered production pipeline fails on every scheduler tick. Deleting script files without migrating or updating `automations.json` breaks live automation state.

**VERIFICATION CRITERION**  
Either `reports/0base_auto.py` is restored, or `storage/automations.json` is updated to point to an existing authorized blueprint (such as `reports/sample_report_blueprint.py`), allowing the automation to run without throwing file-not-found errors.

### F-014: Blocking `process.wait(timeout=1.0)` held under `_proc_lock` in `kill_all()`

- **Severity:** LOW
- **Confidence:** CONFIRMED
- **Category:** PERFORMANCE / CONCURRENCY
- **Invariant:** I-11 (Deadlock Freedom)
- **Location:** `services/runner.py:kill_all:51-80`

**OBSERVATION**  
In `Runner.kill_all()`, the `process.wait(timeout=1.0)` call is executed inside the loop over active processes while holding `with self._proc_lock:`.

**EVIDENCE**  
Lines 51–80 of `services/runner.py`:
```python
with self._proc_lock:
    for name, process in list(self.active_processes.items()):
        ...
        if pid and sys.platform == "win32":
            subprocess.run(["taskkill", "/F", "/T", "/PID", str(pid)], ...)
        ...
        try:
            process.wait(timeout=1.0)
        except Exception:
            pass
    self.active_processes.clear()
```
If a subprocess takes the full 1.0 second to release kernel handles after `taskkill`, `self._proc_lock` is held for up to 1.0 second per active process.

**CONSEQUENCE**  
Any concurrent thread attempting to register a process, query process status, or complete a watcher callback is blocked for up to 1.0 second.

**VERIFICATION CRITERION**  
`process.wait(timeout=...)` or handle reaping occurs after releasing `self._proc_lock`, or uses non-blocking polling (`process.poll()`).

## 5. REFUTED HYPOTHESES

1. **Hypothesis: `taskkill` crashes on already-terminated processes.**  
   *Test:* Spawned an already-dead process (`sys.exit(0)`), added to `active_processes`, and called `kill_all()`.  
   *Result:* Refuted. The `try/except: pass` wrapper around `subprocess.run(["taskkill", ...])` prevents `CalledProcessError` or execution exceptions from escaping.
2. **Hypothesis: Passing `exec_id` breaks legacy tests calling `_watcher()` directly.**  
   *Test:* Executed existing tests in `tests/test_services.py` where `runner._watcher` is called with 5 positional arguments without `exec_id`.  
   *Result:* Refuted. `exec_id: Optional[int] = None` defaults gracefully, reading `getattr(process, "_exec_id", None)` as fallback.
