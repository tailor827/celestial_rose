## 3. Detailed Technical Findings & Resolution Verification

### Finding F-053: Multi-Slot Concurrency Starvation Cooldown Bypass & Asymmetric Fast-Spinning on Lane A Dependency Skips (`max_concurrent_run > 1`)

#### 1. Observation
In [`paradiso/services/intraday_service.py`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/services/intraday_service.py), when multi-slot concurrency is active (`max_concurrent_run > 1`, e.g. default pool size or expanded 2..20) and all queued jobs in a pass skip due to unready dependencies (or enter retrial), fast-finishing jobs were immediately popped from `self.waitlist` and re-dispatched into available concurrency slots during the *same ongoing pass*.

#### 2. Resolution Implemented by Builder
In `IntradayService.tick()`, candidates for dispatch from `self.waitlist` are strictly filtered to unseen reports:
```python
unseen_candidates = [r for r in self.waitlist if r not in self._cycle_seen_in_pass]
```
Reports that finish and rotate to the back of `self.waitlist` remain held until all parallel tasks conclude and the pass completes. Additionally, `_evaluate_pass_completion()` is called if an unseen candidate is found to be disabled.

#### 3. Verification
Verified via `paradiso/artifacts/audits/poc/poc_f053_f054_concurrency_spin_and_delete_leak.py` and dedicated unit test `tests/test_audit_fixes.py:test_f053_multi_slot_seen_reports_do_not_fast_spin_in_same_pass`.

### Finding F-054: `delete_automation` Leaks Runtime Execution State and Storage Run History, Permanently Starving Re-created Reports

#### 1. Observation
In [`paradiso/controllers/automation_controller.py:delete_automation`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/controllers/automation_controller.py), deleting an automation only cleaned `waitlist`, `current_runs`, `active_runs_type_b`, `active_runs_type_c`, and `retry_counts`. It failed to evict runtime tracking state from `type_c_ran_today`, `type_c_retry_after`, `type_c_warned`, `type_b_exhausted`, `type_b_last_run`, `_cycle_pass_reports`, `_cycle_seen_in_pass`, `_last_rotation_logged`, and failed to purge daily execution records from `day.reports_ran` in `intraday.json`.

#### 2. Resolution Implemented by Builder
In `AutomationController.delete_automation()`:
- Purged deleted report name from all Lane A/B/C runtime tracking sets and dictionaries (`type_c_ran_today`, `type_c_retry_after`, `type_c_warned`, `type_b_exhausted`, `type_b_last_run`, `_cycle_pass_reports`, `_cycle_seen_in_pass`, `_last_rotation_logged`).
- Triggered `self.intraday_service._evaluate_pass_completion(today_date)`.
- Invoked `self.intraday_service.intraday_repo.purge_report_from_day(today_date, name)` in `Intraday` model, removing the report from both `reports_ran` and `expected_reports`.

#### 3. Verification
Verified via `paradiso/artifacts/audits/poc/poc_f053_f054_concurrency_spin_and_delete_leak.py` and dedicated unit test `tests/test_audit_fixes.py:test_f054_delete_automation_purges_runtime_and_intraday_state`.
