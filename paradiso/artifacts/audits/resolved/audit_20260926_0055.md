## 3. FINDINGS DOSSIER

### F-028: Pre-existing Finalized Day Record in Storage Paralyses Daily Execution

- **Severity:** CRITICAL
- **Confidence:** CONFIRMED
- **Category:** STORAGE / STATE-MACHINE
- **Invariant:** I-4, I-6, I-8
- **Location:** `paradiso/services/intraday_service.py:start_lane:188-193`, `start_fresh_run:325-331`, `tick:480-487`
- **Replication Asset:** `paradiso/artifacts/audits/poc/poc_f028_preexisting_day_paralysis.py`

**OBSERVATION**  
If a day record for the current calendar date already exists in `storage/intraday.json` with `reports_ran` entries (for instance, created prematurely or auto-finalized by `_reconcile_past_days()`), `IntradayService.start_lane()`, `start_fresh_run()`, and `tick()` populate `already_ran = set(day.reports_ran.keys())`. All expected reports are excluded from the queue, leaving `waitlist` empty.

**EVIDENCE**  
In `IntradayService.start_lane()`:
```python
if norm == "type_a":
    self.lane_a_active = True
    pending = self.automation_service.get_pending_by_type("type_a")
    already_ran = set(day.reports_ran.keys()) if day else set()
    queue_items = [r for r in pending if r not in already_ran and r not in self.current_runs]
    self.waitlist = deque(queue_items)
```
And in `IntradayService.tick()`:
```python
already_ran = set(day.reports_ran.keys()) if day else set()
pending_a = self.automation_service.get_pending_by_type("type_a")
uncompleted = [r for r in pending_a if r not in already_ran and r not in self.current_runs and r not in self.waitlist]
for r in uncompleted:
    self.waitlist.append(r)
```
If `day.reports_ran` contains the day's reports (marked as `"failed"` from `"Historical day finalized automatically"`), `queue_items` is `[]` and `self.waitlist` is empty. The scheduler runs with zero queued reports, and no reports ever execute. Verified via [`poc_f028_preexisting_day_paralysis.py`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/artifacts/audits/poc/poc_f028_preexisting_day_paralysis.py).

**CONSEQUENCE**  
Total operational shutdown for the current calendar day. Financial reports fail to queue or execute because the system mistakenly believes the day has already completed.

**VERIFICATION CRITERION**  
When the engine boots on a new day during `WAITING_TO_OPEN` (00:00–06:59), any pre-existing or prematurely finalized day record must be detected, and a clean operational day slate must be initialized so all expected reports are queued for execution.

### F-029: Mid-Day Process Restart Causes Duplicate Execution of Lane C Timeslot Reports

- **Severity:** HIGH
- **Confidence:** CONFIRMED
- **Category:** STATE-MACHINE / CONCURRENCY
- **Invariant:** I-1, I-4
- **Location:** `paradiso/services/intraday_service.py:__init__:33`, `start_lane:212-220`, `start_fresh_run:330-340`, `tick:522-549`
- **Replication Asset:** `paradiso/artifacts/audits/poc/poc_f029_lane_c_reboot_duplication.py`

**OBSERVATION**  
`IntradayService.type_c_ran_today` is an unpersisted, volatile in-memory set initialized to `set()` upon instance creation. It is never hydrated from `day.reports_ran` when the service starts up or when Lane C is activated mid-day.

**EVIDENCE**  
In `IntradayService.tick()`:
```python
if rep.name in self.type_c_ran_today:
    continue
...
if CLOCK.time_24_str() >= target_time:
    self._trigger_type_c_report(rep.name, today_date)
```
Trace:
1. Report `MID Ledger Reconciliation` (`scheduled_time: "12:00"`) executes and completes at 12:05 PM, recorded in `day.reports_ran`.
2. The server process restarts or redeploys at 14:00 (2:00 PM).
3. A fresh `IntradayService` instance initializes with `self.type_c_ran_today = set()`.
4. On the very first tick at 14:00, `tick()` checks `rep.name in self.type_c_ran_today` (evaluates to `False`) and `CLOCK.time_24_str() >= target_time` (`"14:00" >= "12:00"` evaluates to `True`).
5. `_trigger_type_c_report()` dispatches the report a second time. Verified deterministically via [`poc_f029_lane_c_reboot_duplication.py`](file:///c:/Users/desktop/Documents/work/celestial_rose/paradiso/artifacts/audits/poc/poc_f029_lane_c_reboot_duplication.py).

**CONSEQUENCE**  
Destructive duplicate execution of once-per-day time-pinned reports (e.g., daily cash reconciliation, mid-day ledger feeds, EOD books) whenever the application restarts during business hours, violating the Lane C Daily Execution Invariant.

**VERIFICATION CRITERION**  
On startup, lane start, and tick, `type_c_ran_today` must be hydrated from `day.reports_ran` for the current date, guaranteeing that reports that already completed or finalized today never re-execute after a service reboot.

### F-030: Web UI Silently Swallows HTTP 409 Intraday Window Rejection on Lane Start

- **Severity:** MEDIUM
- **Confidence:** CONFIRMED
- **Category:** UI / HONEST API
- **Invariant:** I-7
- **Location:** `paradiso/web/static/js/app.js:startLane:292-313`

**OBSERVATION**  
In `web/static/js/app.js:startLane(lane)`, the response handler checks only for HTTP 429 (`if (!data.ok && res.status === 429)`). It contains no handling for HTTP 409 Conflict.

**EVIDENCE**  
In `paradiso/web/static/js/app.js`:
```javascript
async function startLane(lane) {
    const key = normalizeLaneKey(lane);
    try {
        const res = await fetch('/api/paradiso/lane/start', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ lane: key })
        });
        const data = await res.json();
        if (data.cooldown_remaining && data.cooldown_remaining > 0) {
            startLaneCooldown(key, data.cooldown_remaining);
        }
        if (!data.ok && res.status === 429) {
            showToast(`Lane cooldown active: please wait ${Math.ceil(data.cooldown_remaining || 10)}s`);
            return;
        }
        await fetchLanesStatus();
        fetchDashboardStats();
    } catch (err) {
        console.error(`Failed to start lane ${key}:`, err);
    }
}
```
When `res.status === 409` is returned, `showToast` is not called, no alert is displayed, and the function silently continues to `fetchLanesStatus()`.

**CONSEQUENCE**  
When an operator clicks "Start Lane" outside the active intraday window (`00:00–06:59`, `21:00–21:59`, or `22:00–23:59`), the UI displays no feedback, leaving the user with no explanation of why the lane did not start.

**VERIFICATION CRITERION**  
`startLane()` in `app.js` must display `data.error` to the operator via toast or alert when HTTP 409 Conflict is returned.

## 4. REFUTED HYPOTHESES

1. **Hypothesis: Multi-slot parallel execution in Lane A (Phase 2.1) causes duplicate dispatches of the same report.**
   - *Attack:* Tested `max_concurrent_run = 5` with 10 pending reports.
   - *Outcome:* `len(current_runs)` strictly respected `min(available_slots, len(waitlist))`, and reports were popped cleanly from `waitlist` without duplicate launches. Invariant held.
2. **Hypothesis: Slot replenishment in Lane A launches more jobs than `max_concurrent_run` allows during rapid callback completion.**
   - *Attack:* Concurrently triggered completion callbacks across parallel slots while `tick()` was executing.
   - *Outcome:* `len(self.current_runs) < self.max_concurrent_run` guard in `tick()` prevented over-allocation. Invariant held.
3. **Hypothesis: Setting `max_concurrent_run` to invalid numbers (e.g. 0, -1, 50, string) via Settings API crashes the scheduler daemon.**
   - *Attack:* POSTed malformed and out-of-bounds `max_concurrent_run` values to `/api/settings`.
   - *Outcome:* `validate_config()` strictly enforced $1 \le \text{max\_concurrent\_run} \le 20$ and returned HTTP 400 Bad Request. Invariant held.
