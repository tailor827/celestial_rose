What is Paradiso & Why Do We Use It?

Understanding sequential queue execution in plain English

In data analytics and operations, scheduling 15 different heavy scripts to run at 8:00 AM can cause database query collisions, CPU spikes, and memory crashes. Paradiso acts as your automated traffic controller: it lines up all daily reports and runs them strictly one at a time.

The 24-Hour Daily Cycle: 4 Work Shifts

🌙 00:00 – 07:00
Reset & Rest
Paradiso resets all daily reports back to Waiting so they are ready for the morning.
☀️ 07:00 – 21:00
Active Work Window
The queue is open! Paradiso picks up reports from the waitlist one-by-one and executes them.
🌆 21:00 – 22:00
Wind-Down Window
No new reports start. Any report already running is allowed to finish naturally.
🛑 22:00 – 23:59
Hard 10 PM Cutoff
Everything stops! Lingering processes are terminated to leave database servers clear for overnight ETL pipelines.

The #1 Rule for Report Scripts: The Receipt Contract

How your Python or R script communicates with Paradiso

💡 Bank-Grade Rule: Silence is not success! In financial pipelines, a script that simply exits with zero output could have died silently. Paradiso requires every script to write a small JSON receipt to paradiso/logs/{report_name}.json before exiting.

The 3 Sovereign Report Outcomes

Completed Extraction Succeeded

Your script queried the database, generated the spreadsheet or deliverable, and saved its receipt. Paradiso logs it as finished and moves to the next report.

Retrial (Skip) Upstream Table Not Ready

Your script detected that yesterday's ledger or source table hasn't posted yet. Instead of crashing, your script emits status: Retrial. Paradiso politely moves your script to the back of the queue to try again later—with zero retry penalty!

Failed Real Code Error

Your script threw an unhandled Python/R exception or syntax error. Paradiso retries it up to 3 times before setting it to Failed. You can inspect the error trace in the Executions tab.

Pre-built templates that automatically comply with the Receipt Contract

Don't build from scratch! Use these official starter templates. They take zero command-line arguments and automatically write their receipts to the right folder: 

import sys
import json
from pathlib import Path
from datetime import datetime

REPORT_NAME = "My_Custom_Report"

def write_receipt(status: str, message: str, deliverable: str = None):
    # Receipts must be written to paradiso/logs/{REPORT_NAME}.json
    base_dir = Path(__file__).resolve().parent.parent / "paradiso" / "logs"
    base_dir.mkdir(parents=True, exist_ok=True)
    receipt_file = base_dir / f"{REPORT_NAME}.json"
    
    data = {
        "report_name": REPORT_NAME,
        "status": status,  # "Completed" | "Retrial" | "Failed"
        "timestamp": datetime.now().strftime("%Y-%m-%d %I:%M:%S %p"),
        "deliverable": deliverable or "None",
        "message": message
    }
    with open(receipt_file, "w", encoding="utf-8") as f:
        json.dump(data, f, indent=2)

    print(f"[{datetime.now()}] Starting {REPORT_NAME}...")

    # 1. Dependency check: is upstream table ready?
    database_ready = True  # Replace with your actual SQL / feed check
    if not database_ready:
        print("SKIPPED: Missing dependency 'raw_transactions_table'")
        write_receipt("Retrial", "Waiting for upstream ledger to post")
        sys.exit(0)

    # 2. Extract & Transform Workload
    try:
        # Perform your pandas / SQL extraction here
        # df = pd.read_sql(...)
        # df.to_excel("reports/output.xlsx")
        
        # 3. Successful delivery
        write_receipt("Completed", "Report processed successfully", deliverable="output.xlsx")
        print(f"[{datetime.now()}] {REPORT_NAME} finished cleanly.")
        sys.exit(0)
    except Exception as e:
        write_receipt("Failed", f"Critical error: {str(e)}")
        print(f"ERROR: {e}", file=sys.stderr)
        sys.exit(1)

if __name__ == "__main__":
    main()

How to Add a Report in 3 Simple Steps

Registering your script on the web dashboard

1

Save Your Script in the Reports Directory

Place your .py or .R script inside the authorized reports/ folder (or reports/python / reports/r). Scripts outside these authorized directories are blocked for security.

2

Open the Automations Tab & Click "+ Add New Report"

In the sidebar on the left, click ⬡ Automations. In the top-right corner, click the + Add New Report button.

3

Fill in the Form & Click "Save & Register Report"

Enter a unique Report Name (e.g. Monthly_Sales_Rollup), select the script filename from the dropdown, choose your interpreter (Python or R), and pick a target run time (e.g. 08:30). Click save, and Paradiso will add it to today's queue!

Decoding Dashboard Badges & Monitoring Logs

What each color means and how to inspect errors

Waiting
Queued in Line: The report is staged and waiting for its turn in the sequential queue.
Running
Currently Executing: Paradiso is actively running this report's subprocess. Only 1 report runs at any given time.
Retrial
Waiting for Upstream Data: The report checked for its dependencies and found they aren't ready yet. It was safely moved to the back of the queue to recheck later with zero retry penalty.
Completed
Successfully Finished: The script finished its calculations and confirmed its delivery receipt.
Failed
Error or Timeout: The script encountered an unhandled error or breached the 10:00 PM cutoff. Click the ▷ Executions tab in the sidebar to view stdout/stderr terminal output.

How to View Terminal Logs

Whenever a script fails or you want to see what it printed:
1. Click the ▷ Executions tab in the left sidebar.
2. Click on the row for your report.
3. A dark console window will open showing the full standard output, error messages, and Python/R stack traces!

Controls & Safety Guardrails Explained

Why certain buttons lock or count down

⏱ Why is there a 10-second countdown after I click Start or Stop?
Paradiso features a Transition Cooldown guardrail. Rapid double-clicking on start/stop buttons could spawn duplicate background threads or corrupt process handles. The 10-second buffer guarantees the scheduler state transitions safely and cleanly.
🔒 Why is the Settings "Save" button disabled with an amber warning?
Paradiso enforces an Idle-Only Settings Guardrail. You cannot reconfigure run hours, directories, or Python paths while reports are actively running in flight. To change settings: simply click Stop Scheduler in the top bar, edit your settings, click Save Configuration, and then click Start Scheduler again.
⚡ How do I test an entire 24-hour day in 2 minutes?
Paradiso includes an accelerated Simulation Mode! Go to Settings ➔ toggle Simulation Mode: Enabled ➔ set Speed Multiplier: 600x (where 1 real second = 10 simulated minutes) ➔ click Save. In the top bar, click Reset (Test) to rewind the clock to midnight, and watch your daily pipeline execute in accelerated time!

Frequently Asked Questions for Analysts

Troubleshooting common issues quickly

Q: My report status says "Contract Violation: missing receipt". What happened?
Your script completed its run (or exited), but failed to write the JSON receipt file to paradiso/logs/{report_name}.json. Ensure your code calls write_receipt("Completed", ...) before calling sys.exit(0).
Q: Can I manually trigger a report to run immediately?
Direct manual runs return 403 Forbidden by design. Paradiso manages execution order sequentially to prevent database overload and lockups. To run your report, make sure its status is set to Waiting and start the scheduler—Paradiso will dispatch it in orderly sequence.
Q: How do I pause a report from running without deleting it?
In the Automations tab, you can set a report's status to Inactive or Disabled. Paradiso will skip disabled reports during midnight resets and daily queue runs.
Q: What happens if my script takes longer than 10:00 PM to finish?
At 22:00 (10:00 PM), Paradiso's hard cutoff activates. Any script still executing will be cleanly terminated using tree-kill, and its status will be marked Failed: breached 10:00 PM cutoff. If your report regularly takes hours to run, consider moving its scheduled start time earlier in the morning.
